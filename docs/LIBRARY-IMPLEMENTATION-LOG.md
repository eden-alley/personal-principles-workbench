## 已确认的实现边界

- 原则为主要长期参考，相关未提炼、未关联原则的收藏素材和已确认经历可以自动补充；不固定每轮携带三类记录。收藏不代表认同，自动读取不自动授权写入，相关反例可挑战旧原则。
- 明确保存意图和精确表述可直接写入并返回程序回执；需要推断或整理时形成可编辑草稿，确认后保存。简单赞同不自动写入。同一回答可带建议，不额外串行调用提炼模型。
- 复用 Source、PrincipleVersion、Observation、Suggestion 与现有领域服务，新增 LibraryEntry、LibraryAsset、LibraryEvidence、LibraryDraft、LibraryTurn、LibraryConversation 等记录补齐所有权、投影状态、轮次与版本依据。
- 新长期库独立使用 WORKBENCH_DATA_DIR=data/librechat-library，包含 workbench.sqlite3 与原件 attachments；旧正式库不迁移、不自动分配所有者。网关启动迁移独立新库。
- 8768 是共享上下文与内部资料 API，8767 是 Codex bridge，3081 是 LibreChat，27018 是独立 MongoDB。聊天由 3081 经 8768 调用 8767；bridge 继续只做模型协议适配。身份来自 LibreChat 服务端登录上下文，内部请求另做鉴权。
- 本地 CPU 语义向量使用 FastEmbed / BAAI/bge-small-zh-v1.5，SQLite 存向量；RapidOCR 处理图片。收藏、原件、解析和索引状态分开，普通聊天不调用付费 OCR/嵌入 API。
- 默认每个对话最多一个自动提议，跨对话至少间隔 20 分钟；用户主动要求草稿不受自动频次限制。可关闭建议；忽略不追问。
- 可逆移出采用回收站，保留旧版本和原件；不冒充永久删除。旧数据迁移、付费 API、发布仍须满足专项授权。

## 已实现与集成修正

- 素材收藏从服务端核验的用户消息和附件取得原件；“先收着”图片及“记住：精确表述”等自然命令接入同一领域保存。模型没有数据库写权限。
- 日常检索最多返回 5 条，并有类型与字符预算；支持最多 5 条指定参考、排除和建议开关。原则优先但允许未关联素材与确认经历自动补充。检索失败有明确反馈，不能假装读过指定资料。
- 程序持久化本轮引用快照。已排除、移除或修订记录衍生的历史回答会在后续上下文处理中排除，避免旧记忆绕回。
- 真实协议核对后，轮次键改用预分配的 assistant messageId，而不是 parentMessageId；重新生成各有独立快照。用户消息 ID 用于收藏来源和保存命令幂等。
- 简短“确认保存/记住这条”只关联当前分支上一助手回答哈希匹配的草稿；原原则的修订新增版本，不覆盖旧理由、表述或依据。
- Library 实体、原件、草稿和引用 ID 均为数字；LibreChat 对话与消息 ID 保持字符串。无标题记录使用 String(id) 展示与精确移除确认。
- 资料库 UI 包含分类/回收站、原文/解析/索引状态、下载、手动新增原则与经历、按标题选择依据、原则版本编辑、精确移除与恢复、导出和对话设置。助手区包含折叠引用、查看与排除、可编辑草稿确认或忽略。
- 历史版本展示当时标题、状态、情境、边界与 evidence 摘录；依据记录名称用当前标题，摘录保留当时快照。JSON 导出包含完整版本依据及原件 data_base64，并覆盖当前账号的全部记录，不受列表最多 200 条的界面限制。
- 历史消息不永久轮询；生成结束刷新本轮记录。资料库仅打开且条目 pending 时轮询，不因普通保存刷新整屏历史轮次。
